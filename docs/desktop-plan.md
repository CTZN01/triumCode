# TriumCode 桌面端产品需求与开发规格

**文档状态：** 已批准的产品设计基线；阶段 B/C/D/E 有实现但尚未通过完整验收；交付优先级见 [`desktop-roadmap.md`](desktop-roadmap.md)
**产品范围：** 面向个人开发者的本地桌面编码 Agent；首发优先支持 Windows，中文界面优先，后续扩展 macOS/Linux。
**目标体验：** 提供与 Codex 同类的核心编码工作流，不复制其品牌、内部实现或所有云端能力。

本文是后续实现的验收依据。开发时每项需求必须标记未开始、进行中、完成或暂缓，并关联代码、测试和文档；不能以“主流程能跑”代替整份需求完成。

## 1. 产品定义

### 1.1 用户问题

开发者需要把一个真实代码项目交给 Agent 完成多步工作，同时仍能看清它正在做什么、它修改了什么、哪些操作需要自己决定，以及失败后如何安全继续。CLI 已有模型、工具和 Agent 循环，但终端交互不适合持续查看会话、比较代码变更、管理多个项目和并行任务。

### 1.2 产品承诺

用户打开一个本地项目后，可以创建或恢复会话，让 Agent 阅读、修改和运行项目；桌面端持续展示任务状态、工具行为和权限请求；用户可以停止任务、检查改动、通过 Git 或终端继续处理，并在应用重启后恢复对话。

### 1.3 目标用户与主要任务

| 用户 | 要完成的事 | 成功条件 |
|---|---|---|
| 独立开发者 | 修 bug、实现小功能、解释代码 | Agent 使用选定项目上下文工作，回答和改动可检查 |
| 日常使用多个仓库的开发者 | 切换项目并恢复旧工作 | 项目和会话明确分组，切换后不会串项目或串历史 |
| 重视操作控制的开发者 | 逐项审核写文件、命令和 Git 操作 | 审批卡片说明具体动作，拒绝不会意外执行 |
| 同时处理多个任务的开发者 | 并行推进互不相关的工作 | 每项任务有独立状态和文件隔离，结果可比较和收尾 |

### 1.4 产品原则

1. **工作区可见：** 每条对话、工具和终端都能明确归属到一个本地目录。
2. **进度可见：** 显示模型响应、工具活动、等待用户的原因和任务最终状态；不展示或伪造模型私有推理内容。
3. **审批可理解：** 在用户批准前说明将执行的程序、参数、目录或将被改写的文件。
4. **修改可检查：** 能区分本轮 Agent 的更改、已有用户改动和 Git 暂存内容。
5. **失败可恢复：** 断网、拒绝操作、取消、崩溃和重启都有明确状态；不自动重放可能产生副作用的命令。
6. **核心共用：** CLI 和桌面端使用同一套 Agent、provider、工具与权限决策，不维护两套 agent loop。
7. **安全声明准确：** UI 隔离、审批和 OS 级沙箱是不同能力，不能互相冒充。

### 1.5 产品成功指标

- 新用户从首次启动到发出第一条有效请求的路径可完成，不需要编辑 JSON 或使用终端。
- 用户可从项目选择开始，完整走通“发起任务 - 查看工具 - 响应审批 - 查看改动 - 继续或结束”。
- 重启后所有已保存用户消息和 Agent 最终回复可恢复；运行中会话明确标记为中断，不伪装成成功。
- 工作区隔离、权限拒绝和任务取消有自动化覆盖；未授权操作不能因窗口关闭、IPC 错误或应用重启而默认获批。
- 首版不默认上传文件、提示词、命令输出或密钥到 TriumCode 遥测服务；默认不引入产品遥测。

## 2. 版本承诺与边界

### 2.1 首版桌面 MVP 必须交付

- 打开、记录并切换多个本地工作区；非 Git 目录也可使用。
- 每个工作区有独立会话列表，可新建、恢复、重命名、搜索和删除会话。
- 流式对话、Markdown/代码块展示、停止任务、模型配置和错误恢复。
- 展示 Agent 的工具开始、结果、失败、问题和审批请求。
- 桌面端有明确权限模式；默认模式对文件修改和程序执行请求用户批准。
- 变更列表和逐文件 diff；对运行前已有用户改动做标识。
- 基础 Git 状态/差异视图和绑定当前工作区的集成终端也属于对外发布的 MVP；阶段 C 是内部 Alpha，完整 MVP 要等阶段 D 通过验收。
- API key 不暴露给 renderer；现有 CLI 可继续独立运行，原有会话不能丢失。

为尽快让用户试用，路线图先交付 Windows x64 便携预览包。当前候选版本及其验收门槛见 `docs/desktop-roadmap.md`。预览包是早期版本，不代表上述 MVP 条目都已验收，也不降低本节退出门槛。

### 2.2 后续 Codex 同类工作流

- 多会话后台运行、任务中心、并行 Agent 和 Git worktree。
- 完整终端、多分支/工作树收尾、可追踪的 Agent 修改审阅与恢复。
- Subagent 任务树和结果导航。
- 技能管理、命令面板、快捷键、通知、自动更新、签名安装包。
- 经过逐平台验证的更强 OS 级进程沙箱。

### 2.3 首版不承诺

- 云端任务、账号登录、跨设备同步、团队协作、远程开发环境。
- 与 Codex 所有功能或界面完全一致。
- 未设计权限和来源校验的插件市场。
- 把普通子进程、Electron renderer sandbox 或用户确认描述为强 OS 沙箱。
- 第一版支持任意 MCP 服务或任意第三方扩展；先完成基础权限与生命周期模型。

## 3. 产品现状与必须处理的差距

- package.json 将程序配置为 Node.js/TypeScript CLI，入口为 src/cli.ts。
- src/agent.ts 已实现模型流、工具循环、子 agent、上下文处理、用量和 abort，但直接调用 src/ui.ts 的终端输出函数。它还提供 setOnChatComplete、setAskUserCallback 和 abort，可作为事件化改造的起点。
- src/cli.ts 依赖 readline、process.stdin 和 process.stdout。桌面端不得调用 CLI 入口模拟 GUI。
- src/session.ts 通过 process.cwd() 找工作区，并使用单个 session-latest 指针供当前 CLI 会话续写。桌面端必须将 workspaceRoot 和 sessionId 显式传入，不能共享一个进程级“当前会话”状态。
- src/permissions.ts 当前规则优先处理 deny/allow，read 工具自动允许；但 default 路径并没有对所有文件写入和普通 run_command 自动要求确认。桌面产品不能把现状文案当作已实现的安全保证，必须补上权限决策、策略测试和 UI 状态。
- src/tools.ts 的 run_command 启动外部程序，默认 cwd 来自进程目录，并设有命令超时；工具层需接收明确的工作区、取消信号和输出生命周期。审批本身并不能把命令限制在工作区内。
- src/config.ts 的 API key 配置目前涉及普通用户配置文件。桌面端需采用受保护的凭据存储，并设计与现有 CLI 配置的导入/共存规则。
- src/providers、src/context-compression.ts、src/memory.ts、src/skills.ts、src/subagent.ts 和 src/tool-executor.ts 是可复用能力，但各自的工作区依赖、生命周期和状态展示需要纳入接口设计。

## 4. 信息架构与页面设计

### 4.1 主窗口结构

桌面主窗口分为三块，可折叠/调整宽度，尺寸不足时先折叠右侧面板，不隐藏当前任务状态：

1. **左侧导航：** 新建工作区、最近工作区、当前工作区会话列表、会话搜索、新建会话。
2. **中央工作区：** 顶部当前项目/分支/模型/权限模式；中间消息与工具活动时间线；底部输入框。
3. **右侧检查面板：** 变更文件、任务活动、Subagent 或会话详情；底部/抽屉提供终端入口。

### 4.2 全局导航

- 工作区列表始终可见；每个条目展示名称、路径末级目录、Git 分支和运行状态徽标。
- 会话按最近更新时间排序，显示标题、更新时间、模型标签和运行状态。
- 提供全局设置入口和应用状态提示；密钥状态只显示“已配置/未配置”，不得显示完整值。
- 当前工作区不存在或不可访问时显示修复/移除入口，不静默切换到其他目录。

### 4.3 对话页

- 顶栏：工作区名称、当前 Git 分支（若有）、当前模型、权限模式和任务操作。上下文与 token 用量置于会话信息，避免顶栏堆叠。
- 时间线：用户消息、Agent 文本、工具活动、用户问题、权限请求、错误和状态转移均为独立可读条目。
- 工具活动默认折叠；展开后显示工具名、经过脱敏的输入摘要、执行目录、开始/结束时间、状态和结果。不得把一大段 stdout 塞进不可折叠消息。
- Agent 文本支持流式 Markdown、标题、列表、代码块、复制代码、复制消息和外部链接确认。禁止未经消毒的 HTML 直接渲染。
- 思考状态只显示“正在处理”、当前工具和经过时间；不显示 hidden reasoning。
- 输入框支持多行、Enter 发送、Shift+Enter 换行；运行期间当前会话的发送按钮转换成停止按钮。首版不默默排队第二条用户消息。
- 输入区可为当前空闲会话选择命名模型预设和思考深度；变更从下一条消息生效并持久保存，运行中禁止切换。自定义路由通过设置页编辑。
- 输入为空、正在审批、请求失败、已停止和正在恢复时均有明确按钮状态。
- 后续加入文件引用/拖放附件时，必须显示附件路径/名称，并明确图片或二进制文件是否会发送给模型。

### 4.4 变更检查页

- 按文件列出本轮修改、新增和删除；可展开查看统一 diff，并定位到文件/行。
- 区分“本轮开始前已存在的改动”和“本轮之后新增的改动”，Git staged、unstaged、untracked 分区展示。
- 非 Git 目录仍需按工具写入活动展示本轮修改；不能因为没有 .git 就声称没有改动。
- 用户点击撤销/还原时，说明将覆盖的内容并二次确认；若文件在 diff 生成后又发生变化，禁止直接用旧快照覆盖。
- 不提供“自动接受所有改动”的隐式按钮；应用工具直接写文件时，审阅是对现有工作树的检查，不代表工具写入前已有补丁预览。

### 4.5 设置页

- **模型与连接：** provider 协议、模型、基础地址、认证方式、思考/effort、连接测试、命名预设。
- **凭据：** 设置/替换/删除 API key；测试连接不在 UI、日志或错误字符串中回显 key。
- **权限：** 默认模式、工作区规则、用户规则、拒绝规则、历史批准记录、各模式行为说明。
- **工作区：** 最近列表、默认模型/权限覆盖、移除最近记录（不删除真实项目）。
- **外观与快捷键：** 主题、面板布局、键盘映射。
- 配置错误按字段定位，保留用户输入，提供可理解的修复动作。

## 5. 关键用户流程

### 5.1 首次启动

1. 展示产品用途和本地权限说明；不自动扫描用户硬盘。
2. 用户选择一个项目目录；允许非 Git 项目。
3. 用户选择模型预设或输入 provider、API 地址、协议和 key。
4. “测试连接”显示连接中、成功、认证失败、网络错误和协议错误，不泄露密钥。
5. 成功后进入空会话页；失败时可修改设置或进入设置页，不丢弃目录选择。

### 5.2 创建与继续会话

每个桌面会话保存模型名、命名预设身份、API 端点、协议、认证类型、扩展思考开关、effort 和上下文窗口；快照禁止包含 API Key。更改桌面偏好只影响新会话；当前会话只能在空闲时显式切换预设或 effort，下一条消息使用新路由。旧版会话缺少快照时，保留其已保存模型名，并在首次打开时用当前桌面配置补齐其余路由字段。

1. 用户点击新建会话，AgentHost 绑定 workspaceId、规范化后的 workspaceRoot、sessionId 和当前设置快照。
2. 用户发送非空消息；主进程确认工作区存在并加载权限/上下文。
3. 时间线上先显示用户消息和运行状态，再显示流式响应与工具事件。
4. 完成后保存消息、模型路由、更新时间、token/用量摘要和最终状态。
5. 重启后恢复历史；运行中崩溃的任务显示为“意外中断”，不自动重新执行工具。

### 5.3 权限请求

1. Agent 请求未允许的操作时暂停对应工具，显示独立审批卡片。
2. 卡片展示具体动作、路径或程序与参数、执行目录、触发工具、策略来源（桌面默认策略或命中的用户/项目规则及设置文件），是否会访问工作区外资源（可判断时）。不确定时明确标记“无法判断”，不猜测。活动面板持久记录策略决定和一次/本会话授权、拒绝、超时或取消结果；来源必须来自权限决策对象，不能从工具输出文字推断。
3. 用户可选“允许这一次”“本会话允许相同操作”“拒绝”。本会话授权仅匹配相同工具、工作区路径和完整参数，与对话一起保存在本地会话文件中，重启后继续有效；详情面板必须列出授权范围并提供撤销入口，明确说明撤销只阻止后续调用、不停止已启动操作。任何用户/项目持久规则都须另行进入权限设置明确创建，不能将一次性按钮悄悄变成全局授权。
4. 拒绝返回工具结果给 Agent，由 Agent 决定是否继续；拒绝不标记为应用错误。
5. 任何 deny 规则优先级高于 allow、模式和 session grants；renderer 断开、用户未选或应用退出一律视为未批准。

### 5.4 计划与计划审批

1. 计划模式只允许读取、提问、规划和计划文件操作，不允许任意写文件或命令。
2. 展示计划正文及“执行”“继续规划”“取消”等明确选项，记录用户选择。
3. 用户选择执行后，明确显示接下来应用的权限模式；不得因离开计划模式自动进入无确认模式。

### 5.5 检查改动并收尾

1. 用户从会话活动或右侧变更计数打开本轮改动。
2. 变更视图显示文件清单和 Git 基线差异；用户原有未提交改动不归因于 Agent。
3. 用户可继续提问、打开文件/终端、复制 diff，或在后续阶段执行 stage/commit。
4. 用户删除会话不会删除工作区文件；用户移除工作区仅移除最近列表，不删除目录。

### 5.6 停止、关闭和恢复

- 用户停止任务：立即停止 API 流，取消尚未启动的工具，并终止可终止的运行中子进程；已完成的文件写入不自动回滚。
- 有未完成任务时关闭窗口：弹出“取消任务并退出”或“返回应用”；首版不提供窗口关闭后继续执行的后台任务承诺。
- 退出时有未响应审批：拒绝该审批并取消相应运行，不保留一个隐式待批准操作。
- 应用崩溃/强退后：下次启动恢复已保存消息和活动日志，标记任务中断；提示用户先检查工作区后再重试。

## 6. 功能需求与验收标准

以下 ID 是产品需求的追踪键。阶段验收必须逐项回填状态和证据。

### 6.1 工作区与导航

- **WS-01 打开项目：** 使用系统目录选择器选择文件夹；取消不改变当前项目。目录不可读时显示路径和重试/移除操作。
- **WS-02 非 Git 目录：** 项目不含 Git 标记仍可创建会话、读写文件和查看工具写入活动；Git 区域显示“未初始化 Git”，不报成崩溃。
- **WS-03 最近项目：** 保存本机最近打开列表；路径无法访问时保留可移除记录，不自动改绑同名文件夹。
- **WS-04 多工作区隔离：** 切换项目后会话、权限规则、cwd、memory 注入、工具调用和变更基线均引用正确的 workspaceRoot。
- **WS-05 工作区生命周期：** 移除项目只删最近记录；删除目录永远要求操作系统确认之外的显式用户动作，本产品首版不提供删除目录功能。
- **WS-06 单实例与路径规范化：** 同一物理路径不同大小写/分隔符不生成两个 Windows 项目；符号链接和 junction 的策略在架构阶段确定并测试。

### 6.2 会话和历史

- **SES-01 新建/恢复：** 可创建空会话，打开任意历史会话，切换后不把新消息写入错误会话。
- **SES-02 管理：** 支持标题、搜索、按更新时间排序、删除确认；删除会话不删除项目文件和记忆。
- **SES-03 自动保存：** 用户消息在启动请求前落盘；assistant 增量按安全检查点保存，至少在工具副作用前后、轮次结束和任务状态变化后保存。
- **SES-04 恢复中断：** 恢复页面能分辨完成、失败、用户取消和异常中断；不自动重放工具调用。
- **SES-05 CLI 兼容：** 桌面端能读取现有 CLI 会话；桌面新会话有明确兼容策略，CLI 对旧格式继续可用；迁移失败不得覆盖或删除源文件。
- **SES-06 并发冲突：** 同一 session 被 CLI、两个窗口或两个任务同时写入时有锁或版本冲突检测，不能静默丢失较新的消息。
- **SES-07 删除与隐私：** 清除会话说明删除范围；会话文本和工具输出只写本地指定数据目录，按用户删除动作清除。

### 6.3 对话与任务

- **CHAT-01 流式输出：** 增量按到达顺序渲染；同一事件重放不重复文本；流中断保留已收到内容并显示状态。
- **CHAT-02 Markdown：** 常用标题、列表、链接、表格和代码块可读；代码复制不含 UI 标签；外部链接用系统浏览器且经过确认/白名单策略。
- **CHAT-03 用户输入：** 多行输入、明确快捷键、空消息阻止发送；运行中不丢用户文本，不意外因 Enter 连发。
- **CHAT-04 提问：** Agent ask_user 的选项题和自由文本题使用不同控件；跳过/关闭返回明确的 skip，不伪造用户回答。
- **CHAT-05 上下文与用量：** 显示模型、上下文使用率和可用用量；隐藏不可提供的数据，不将未知显示为零。自动压缩前后给出简短状态提示。
- **RUN-01 状态机：** 状态至少包含准备、运行、等待审批、等待用户、停止中、完成、失败、取消和异常中断。所有状态有可达路径、可见文案和终止条件。
- **RUN-02 单会话并发：** 同一会话最多一个活动轮次；重复发送被阻止或明确排队，不能并发篡改同一消息历史。
- **RUN-03 取消：** 点击停止后 UI 立即反馈；Agent API、工具队列和子进程按 runId 取消；不可取消的系统调用显示正在停止和最终结果。
- **RUN-04 错误：** 网络、认证、速率限制、provider 协议、工具和内部错误分类型；展示可重试操作；重试不重复插入用户消息或已经执行的工具。安全重试只对瞬时失败且尚未启动任何工具的轮次开放；工具一旦启动，必须先检查工作区，再将恢复请求作为新消息发送，并明确说明已有副作用不会回滚。
- **RUN-05 进程恢复：** 应用启动扫描活动 run；旧 run 转为 interrupted 并显示活动摘要，所有未决批准归为拒绝。
- **RUN-06 事件排序：** 每个事件含 runId、sessionId、递增序号/唯一 ID 和时间；过期 run 的事件不能污染新会话。

### 6.4 工具活动与子 Agent

- **ACT-01 工具时间线：** 记录工具名、可读摘要、开始/结束、状态、结果摘要、错误和所属会话/run；显示不依赖 stdout 字符串猜测。
- **ACT-02 输出处理：** 结果可折叠、复制；超长输出分页/截断且保留查看原始结果的明确入口；输出中的 ANSI、HTML、脚本和恶意链接不能控制应用界面。
- **ACT-03 秘密脱敏：** API key、认证头和配置秘密在工具参数、错误、诊断日志和导出文件中脱敏。
- **ACT-04 Subagent：** 展示委派任务描述、类型、运行/结束/失败状态、token 摘要和最终答复；不要求展示模型私有推理；取消父任务时取消其子任务。
- **ACT-05 工具目录：** 新工具的可见名称、描述、权限分类、并发分类和 UI 摘要有单一映射；工具变更必须补对应测试和文档。

### 6.5 权限与信任

桌面产品采用以下用户可理解的权限模式；底层名称可在实现时映射到现有 enum，但行为必须满足本表：

| 桌面模式 | 读取/搜索 | 文件写入 | 普通程序/命令 | Git 状态写操作 |
|---|---|---|---|---|
| 默认确认 | 工作区内自动允许 | 每次请求用户 | 每次请求用户 | 每次请求用户 |
| 规划 | 允许读取/提问/计划文件 | 其他写入阻止 | 阻止 | 阻止 |
| 接受文件编辑 | 自动允许 | 工作区范围内自动允许 | 每次请求用户 | 每次请求用户 |
| 明确全部允许 | 自动允许 | 自动允许 | 自动允许 | 自动允许；需明显模式标记和退出入口 |

- **PERM-01 请求内容：** 文件操作显示绝对路径、操作类型及覆盖/创建风险；命令显示可执行文件、参数、cwd、超时与输入输出策略；Git 操作显示具体 subcommand 和目标路径。
- **PERM-02 决策来源：** 卡片/活动面板显示默认策略、用户规则、项目规则、临时批准或 deny 规则来源。
- **PERM-03 优先级：** deny 永远胜出，不受模式、一次允许或持久 allow 覆盖；有 deny 时解释拒绝原因。
- **PERM-04 授权范围：** 一次批准仅授权一个具体规范化操作；会话级授权必须展示匹配范围和撤销入口；持久规则必须在设置页确认并保存。
- **PERM-05 默认安全：** 默认确认模式中，非危险的 run_command 和文件修改也需要批准。这是桌面行为要求，不能沿用现有策略的隐含放行行为。
- **PERM-06 工作区边界：** 默认读写根为当前 workspaceRoot；绝对路径、路径穿越、符号链接、junction、大小写和 Windows UNC/设备路径均由同一规范化层判定。访问根外资源时阻止或明确请求额外授权。
- **PERM-07 运行命令边界：** UI 的审批不是沙箱。默认模式下所有外部程序启动都需确认；输出长度、运行时间和子进程树均有上限/取消策略。若程序可联网或访问工作区外资源，卡片不得宣称已隔离。
- **PERM-08 应用边界：** deny 规则和权限策略只在主进程计算；renderer 只能提交用户选择，不能传入“已批准”的任意工具执行命令。
- **PERM-09 审批生命周期：** 关闭窗口、拒绝、超时、IPC 断开和重启都不能转为 allow；待审批操作的状态和原因可追踪。
- **PERM-10 强沙箱路线：** 公开发布前评估 Windows OS 级隔离方案并验证读写/网络边界；若实现不了，则明确产品保护等级，不宣传强沙箱。

### 6.6 代码审阅、Git 和终端

- **REV-01 任务基线：** 每次 run 记录 Git 状态/差异基线；没有 Git 时记录可行的文件工具前后快照。不能把所有工作树差异都算作本轮产物。
- **REV-02 用户既有改动：** 任务开始前已 modified/staged/untracked 的文件独立标记；Agent 改到既有脏文件时突出显示并保留原内容变化，不自动清理。
- **REV-03 Diff：** 支持按文件/状态筛选、展开/折叠、行号和大文件截断提示；差异来自当前文件状态，文件变化后刷新或标记 stale。
- **REV-04 撤销：** 撤销前确认目标和覆盖风险；只在当前文件版本与审阅快照一致时恢复；若版本不同则要求用户手动解决。
- **GIT-01 只读 Git：** MVP 提供仓库/分支状态、工作区 diff、staged diff 和路径级信息；非 Git 项目优雅降级。
- **GIT-02 写 Git：** stage、commit、checkout、reset、clean、push、branch/worktree 删除等动作独立展示目标并要求用户操作/审批；危险操作不能藏在普通按钮里。
- **TERM-01 集成终端：** 每个终端绑定一个 workspaceRoot，标题始终显示当前目录和 shell；终端中的命令由用户亲自输入，不伪装成 Agent 工具。
- **TERM-02 生命周期：** 终端可新建、关闭、重启；关闭前对正在运行进程提示；输出限流、ANSI 安全处理、退出码可见。
- **TERM-03 终端与 Agent：** 终端 cwd 与 Agent 工具 cwd 不共享可变全局状态；两者并行时分别显示；用户可将终端命令显式复制到输入框。
- **TERM-04 平台：** Windows 首发优先 PowerShell；shell 不可用时给出选择/修复，不静默切换到不可预期的 shell。

### 6.7 配置、凭据和桌面壳

- **SET-01 首次配置：** 支持至少一个已实现 provider 的引导；其余现有三种协议的功能按兼容矩阵验证，不假定所有 provider 具备相同可选参数。
- **SET-02 配置校验：** URL、protocol、auth、model、contextWindow 等字段按现有 config 约束校验；不同模型预设可切换 endpoint/protocol/key。
- **SET-03 秘密存储：** 新桌面 key 使用系统保护能力存储；在保护能力不可用时禁用明文持久保存或向用户解释并请求显式选择。
- **SET-04 CLI 共存：** 可导入现有 ~/.triumcode/config.json 与模型预设；导入不删除/改写 CLI 文件。桌面与 CLI 后续对共享配置的读写规则必须版本化。
- **APP-01 Electron 隔离：** contextIsolation、sandbox、禁用 nodeIntegration；限制 preload API；所有 IPC 参数用 schema 校验，拒绝未知字段和过期 runId。
- **APP-02 外部导航：** renderer 不可任意开新窗口或载入远程网页；外部浏览器只能由主进程针对经过校验的链接打开。
- **APP-03 主题与窗口：** 记忆窗口尺寸、面板宽度和主题；窗口缩小时主要操作仍可访问；加载/空状态/错误状态均有设计。
- **APP-04 快捷键与可访问性：** 常用操作有可发现快捷键；键盘可导航菜单、审批卡片和 diff；颜色不是唯一状态区分。
- **APP-05 崩溃与更新：** 更新前保留本地数据；安装失败可重试/回滚；崩溃恢复不自动执行旧命令。

### 6.8 多任务与工作树

- **PAR-01 任务中心：** 列出运行、等待审批、等待用户、完成、失败和中断的任务；从任务中心跳回对应会话和事件位置。
- **PAR-02 并发：** 同一 session 一个活动 run；不同 session 并发数有限且可配置，达到上限时显示排队或拒绝原因。
- **PAR-03 工作树创建：** 用户选择基准分支/提交、任务名称和目标目录；重复分支名、已有目录、dirty 工作区均先处理冲突。
- **PAR-04 工作树隔离：** Agent 路径、Git 操作、终端和 session 全部绑定同一 worktree；不能让两个并行 Agent 默认写同一目录。
- **PAR-05 合并/收尾：** 对比基线、展示冲突、允许用户打开终端处理；删除 worktree 前检查未提交改动并二次确认；保留/删除分支选择明确。
- **PAR-06 父子 Agent：** 父任务取消时子任务和等待槽位可释放；UI 汇总子任务但保留每个子任务的错误与结果。

## 7. 状态模型与异常行为

### 7.1 Run 状态

准备中 -> 运行中 -> 完成 / 失败 / 用户取消 / 异常中断。运行中可进入等待审批或等待用户，再回到运行中；停止请求经过停止中后到用户取消、完成或失败。异常中断只由进程退出恢复流程产生。

每个终止状态有时间、原因和可执行下一步。状态不可从失败/取消回到运行中；重试创建新 run，并引用原 run，不覆盖原活动记录。

### 7.2 Tool 状态

排队 -> 等待审批 -> 执行中 -> 成功/失败/取消/拒绝。拒绝是正常用户决策，不等同工具崩溃。工具执行完成后若进程响应已取消，结果应落入原 run 的活动记录，不得注入另一个 session。

### 7.3 审批状态

待处理 -> 一次允许/拒绝/过期拒绝/因取消撤销。应用没有任何默认允许的终态。每条审批有 requestId、runId、工具输入摘要、规范化资源、策略来源和决策时间。

### 7.4 必须设计的异常场景

- API key 缺失、无效、provider 端点不可达、协议不匹配、限速、响应为空、流式中途断开。
- 用户停止时正有工具排队、运行中命令、审批等待、子 agent、计划审批或 Agent 自动压缩。
- 项目目录被移动/删除、权限被撤销、磁盘只读/空间不足、符号链接指向根外路径。
- Agent 写文件与外部编辑器同时写入；同一会话被两进程打开；Git index 在 diff 显示期间改变。
- 应用崩溃发生在写文件前后、API 收到请求但 UI 尚未显示、审批刚批准但工具尚未启动。
- 终端进程树退出不完整；renderer reload、窗口关闭、系统睡眠/恢复和系统重启。

上述场景必须定义：用户看到的状态、落盘数据、是否重试、是否可能重复副作用、下一步操作。不确定安全性的动作按拒绝处理。

## 8. 数据和配置方案

### 8.1 核心实体

- **Workspace：** 稳定 ID、规范化路径、显示名、最近打开时间、Git 根/分支快照、工作区默认设置。
- **Session：** ID、workspaceId、标题、消息、创建/更新时间、provider/model route、权限模式快照、上下文与用量摘要。
- **Run：** ID、sessionId、状态、用户消息关联、开始/结束时间、模型快照、取消原因、错误摘要、父任务/子任务关系。
- **Activity：** ID、runId、序号、类型、工具名、展示摘要、开始/结束、状态、可折叠结果引用、敏感字段标记。
- **ApprovalRequest：** requestId、runId、toolCallId、规范化操作、策略来源、候选选择、最终决策。
- **ChangeSnapshot：** runId、开始基线、变更文件、文件版本/哈希、diff 引用、stale 状态。
- **TerminalSession：** id、workspaceId、shell、cwd、生命周期、退出码；首版不持久化完整终端滚屏到会话历史。

### 8.2 持久化约束

- 保持 CLI 原有会话可读；设计 SessionStore 适配层后再迁移文件格式。
- Desktop 使用稳定 workspaceId/sessionId 调用存储，不依赖单一 latest pointer；CLI adapter 可继续保留“最近会话”语义。
- 桌面索引/窗口偏好放在 Electron userData；项目会话与 CLI 的兼容策略由版本化 schema 管理。
- 每次 schema 迁移先备份/原子写，能回滚；迁移测试覆盖旧格式、半写文件和重复运行。
- 用户消息在发请求前保存；工具副作用及审批决策的活动事件在执行前后保存；写入采用原子替换并检测版本冲突。
- API 密钥和 credentials 不进入会话 JSON。工具输出大小有限；是否保存原始输出由用户可见的本地保留策略决定。
- 指标/日志默认仅本地；导出诊断需用户触发并可先预览脱敏内容。

## 9. 技术架构与接口边界

### 9.1 选型

- 保持当前仓库；初期新增 apps/desktop，不复制核心实现。
- Electron + React + TypeScript；Windows 先行。Electron 负责窗口与桌面集成，Agent 和工具在主进程/独立 host 中运行，renderer 只负责展示。
- 初期核心仍在 src/；稳定后再抽 packages/agent-core，CLI 再迁入 apps/cli。提取必须是机械/接口重构，不顺带重写 agent loop。
- Electron、React、打包器、终端 PTY、schema validator 等会增加依赖；实现前遵循 AGENTS.md 的新增依赖审批要求，并记录每个依赖的替代评估。

### 9.2 分层

    React Renderer
      -> 受限 preload API
        -> schema 校验的 typed IPC
          -> Electron Main / Desktop Host
            -> AgentHost、WorkspaceService、SessionStore、PermissionService
              -> 现有 Agent、providers、tools、permissions、memory、skills

- Main 进程掌握工作区授权、凭据、Agent 实例和工具执行。
- Preload 只暴露窄接口，例如 workspace.open、session.list、run.start、run.cancel、approval.respond 和 event.subscribe；不暴露通用 ipcRenderer 或任意 Node API。
- Renderer 传入用户选择和显示动作，不传“信任结果”；主进程重新加载资源、计算权限并校验状态。
- 长任务事件带 requestId/sessionId/runId/eventId；用户输入和审批带幂等 requestId，重复 IPC 不重复触发请求或工具。

### 9.3 Agent 核心事件

至少定义并测试以下事件，不以终端打印文本作为协议：

- turn.started、assistant.delta、assistant.message.completed。
- status.changed、thinking.started/ended、usage.updated、context.compaction.started/completed。
- tool.queued、tool.approval.required、tool.started、tool.output、tool.completed、tool.failed、tool.denied。
- user.question.required、user.question.answered、plan.approval.required、plan.approval.resolved。
- subagent.started/updated/completed/failed。
- turn.completed、turn.failed、turn.cancel_requested、turn.cancelled、turn.interrupted。

事件字段包含版本、sessionId、runId、单调序号、eventId 和可序列化 payload。事件输出不携带私有推理块或完整凭据。Renderer 不可靠或关闭时，主进程仍须正确拒绝未处理审批并持久化最终状态。

### 9.4 AgentHost 命令

- createSession(workspaceId, settings)
- loadSession(workspaceId, sessionId)
- startRun(workspaceId, sessionId, userMessage, runOptions)
- cancelRun(runId, reason)
- respondToApproval(requestId, decision)
- respondToQuestion(requestId, answer)
- listWorkspaces/listSessions/listRuns/getActivities

所有 API 校验调用方、工作区注册状态和当前 run 状态；IPC 错误有机器可识别 error code 和用户可读文案。

## 10. 分阶段实现计划与退出门槛

本阶段计划定义产品完整度和验收门槛；交付顺序优先按 `docs/desktop-roadmap.md` 的 Windows 预览版执行。预览版可先交付已经实现的核心闭环，但未完成的需求必须保留为进行中，不能把预览版称作完整桌面 MVP。

### 阶段 A：产品/技术基线

- 把本规格的需求 ID 加进实施任务和验证矩阵。
- 确认 Electron 与核心进程的边界、session 兼容策略、Windows 路径策略、权限默认行为和 OS 沙箱公开承诺。
- 画出首版主窗口、对话页、审批卡片、变更页、设置页和关键错误状态的线框；重要流程先做可点击原型或截图稿再开始全量 UI。
- 梳理现有工具清单、权限决策、读写路径、cwd、进程退出和 provider 事件；建立现状/目标对照表。

**退出门槛：** 没有待决的高风险接口选择；所有 MVP 需求有 ID、负责人/目标阶段和验证方法；用户体验稿覆盖正常、等待、失败、取消、空状态。

### 阶段 B：Agent 核心事件化与显式工作区

- 新增 Agent event sink/host facade；将 src/agent.ts 的 print*/stream/status 调用改为事件。
- 给 CLI 建事件适配器，保持现有终端行为和命令；补事件顺序、错误、取消和权限测试。
- 将 workspaceRoot/sessionId/settings/approval/question/cancel 明确传入 Agent、ToolContext、PermissionPolicy、SessionStore 和 memory。

## 14. 首个开发任务的完成标准

第一轮实现只从阶段 A/B 的一条端到端切片开始，不立即铺开全部页面：

1. 一个明确 workspaceRoot 下创建 session。
2. 用户发送一句话，Agent 事件通过 host 到达测试 UI/CLI adapter。
3. Agent 发起文件写入或命令时，桌面默认模式发出审批请求，拒绝后工具未执行。
4. 用户允许一次后工具执行，工具活动和结果按事件顺序展示。
5. 用户停止请求后 API 流和可取消子进程停止；当前会话状态落盘。
6. 重启或重新加载后可看到会话和最终/中断状态，不重复执行旧工具。
7. 第二个工作区同时运行测试 Agent，不发生路径、会话或审批串线。
8. 现有 CLI 入口继续可用，旧格式会话可读取。

只有这条切片通过，才开始扩展完整的工作区侧栏和桌面页面；之后每个阶段按 ID 验收，不能以视觉样稿或空壳 Electron 窗口计为桌面 MVP。

### 15.2 当前技术约束

- 桌面开发工具链使用 `electron-vite` 5 / Vite 7 和 Electron `^44.4.5`；Electron 当前要求 Node.js 22.12 或更高版本。CLI 仍支持 Node.js 20。PTY 使用 `node-pty` 发布的 Windows N-API 预编译模块，终端显示使用 `@xterm/xterm` / `@xterm/addon-fit`；服务明确选择 Windows ConPTY，避免依赖本地 C++ 编译器和 Spectre 库。
- Renderer 不持有 Agent/provider 实例，不读文件系统，不直接访问网络 API；API key 通过主进程读取，系统 `safeStorage` 加密后落盘，renderer 只接收凭据状态。
- 桌面会话保存模型路由和推理设置快照，不保存 API Key；命名预设使用预设名作为凭据槽位 identity，自定义路由使用独立默认槽位。旧版 v1 凭据仍作为自定义路由凭据读取。
- 代码审阅快照中的文件前置内容也通过系统 `safeStorage` 加密，保存在 Electron userData；每工作区最多保留 20 轮已结束任务，每轮最多保留 8 MiB、单文件最多 2 MiB。超出上限或系统安全存储不可用时，界面必须标记审阅不完整，不能提供该文件的撤销。
- 工具审批 UI 展示脱敏后的操作摘要。根外路径当前直接拒绝，尚无额外授权流程；普通命令可能访问网络或工作区外资源，产品不会把审批描述为 OS 沙箱。
- Markdown 使用 React 文本节点渲染；不使用原始 HTML。对话链接仅允许绝对 HTTPS URL，目标交由主进程确认后在系统浏览器打开；其他协议保持为不可点击文本。
- Electron 39 安装链的 `extract-zip` 曾触发 2 个 high 公告；Electron 已升级到 44.4.5 并改用 `@electron-internal/extract-zip`。2026-09-26 的 `npm audit` 与 `npm audit --omit=dev` 均报告 0 个漏洞。升级需要 Node.js 22.12 或更高版本进行 Electron 安装和桌面开发；CLI 仍支持 Node.js 20。
